# Claude in Chrome ドメイン制限バグ — 回避ガイド

> 対象バージョン: Claude in Chrome v1.0.66〜v1.0.68
> 最終更新: 2026-04-15
> ステータス: Anthropic P1（最優先）修正中
> 検証済み: Desktopチャット委譲方式で KDP フォーム入力成功を確認（2026-04-15）

---

## このガイドについて

2026年4月のアップデート以降、Claude in Chromeで
一部の外部サイトへのアクセスがブロックされるバグが発生しています。

**これはあなたの設定の問題ではありません。**
Anthropic社が公式にP1バグとして認定し、修正中です。

このガイドでは、バグの影響を受けずに作業を続ける方法を説明します。

---

## 影響を受ける操作

| 操作 | 影響 |
|------|------|
| Claude CodeからKDP / GitHub / X等への自動ナビゲーション | ❌ ブロック |
| Claude Codeからのページ読み取り（非Googleドメイン） | ❌ ブロック |
| Claude Codeからのフォーム入力・クリック（非Googleドメイン） | ❌ ブロック |

## 影響を受けない操作

| 操作 | 状態 |
|------|------|
| Claude Codeのコード生成・テキスト処理 | ✅ 正常 |
| Claude Codeのファイル操作・EPUB生成 | ✅ 正常 |
| Claude Codeからのローカルプレビュー（localhost） | ✅ 正常 |
| Claude Codeからのgoogle.comドメイン操作 | ✅ 正常 |
| **Claude Desktopチャットからのブラウザ操作** | ✅ 正常 |

---

## 回避方法

### 方法1: Claude Desktopチャットに切り替える（推奨・検証済み）

Claude Codeではなく、Claude Desktopの通常チャットからブラウザ操作を行います。

**重要な知見（実証実験で判明）:**
- プロンプトは「コピペで即座に動く形式」にする
- 最初の1行に「Claude in Chromeを使用してブラウザ操作を行ってください」を入れる（トリガー文）
- 説明文と指示文を混ぜない（成功率が下がる）
- データは全てプロンプト内に含める（別ファイル参照にしない）

**手順:**

1. Claude Desktopアプリを開く
2. 新しいチャットを開始する
3. 以下のようなプロンプトを貼り付ける

**成功するプロンプトの形式:**
```
Claude in Chrome を使用してブラウザ操作を行ってください。

## 手順
1. https://kdp.amazon.co.jp にアクセス
2. 以下のデータを各フィールドに入力

## 入力データ
- 本のタイトル: ○○○
- タイトルのフリガナ: ○○○
- （以下、全データをここに記載）

## 停止条件
- 「出版」ボタンは押さない
- 入力完了後スクリーンショットを撮って報告
```

4. 初回のみ: ドメインの承認ダイアログが表示されるので「許可」をクリック

**ポイント:**
- 一度承認したドメインは次回以降も有効
- Claude in Chromeの設定画面（Options）で承認済みサイトを確認できる
- `/book-run` の Phase 7 で、このプロンプトを自動生成できる

**うまくいかない場合:**
- Claudeの応答が中断された → 「続けて」と入力
- ドメイン許可のダイアログが出ない → Chrome拡張の設定画面でサイトを手動追加
- フィールドが見つからない → 「ページをスクロールして」と指示

---

### 方法2: 手動タブ + 読み取り指示

対象サイトを先に手動で開いておき、Claudeには読み取りだけを指示します。

**手順:**

1. Chromeで対象サイト（KDP等）を手動で開く
2. そのタブをMCPタブグループにドラッグして追加する
3. Claude Desktopチャットで指示:

```
現在開いているKDPのページを読み取ってください
```

---

### 方法3: 分業フロー（最も安定）

Claude Code（司令塔）とClaude Desktopチャット（実行役）を組み合わせます。

```
┌──────────────────────────────┐
│ Claude Code（司令塔）          │
│ ・コンテンツ生成               │
│ ・メタデータ作成               │
│ ・EPUB変換                     │
│ ・チャット用プロンプト自動生成  │
└──────────┬───────────────────┘
           ▼ プロンプトをコピペ
┌──────────────────────────────┐
│ Claude Desktopチャット（実行役）│
│ ・KDPフォーム入力              │
│ ・外部サイトの読み取り         │
│ ・ブラウザUI操作               │
└──────────────────────────────┘
```

**具体例: KDPに書籍情報を入力する場合**

Step 1: Claude Codeで `/book-meta` を実行
→ メタデータファイル（kdp-fields.md）が生成される

Step 2: Claude Codeに「Desktopチャット用プロンプトを生成して」と指示
→ コピペ用のプロンプトが出力される

Step 3: そのプロンプトをClaude Desktopの新規チャットにペースト

Step 4: Desktopチャット側のClaudeがKDPフォームに自動入力

---

## バグが修正されたかの確認方法

Chrome拡張は自動更新されます。以下の手順で修正状況を確認できます:

1. Claude Codeを起動
2. 以下を入力:
```
Claude in Chromeで https://x.com にアクセスして
```
3. エラーが出なければ修正済み → 通常運用に戻してOK
4. エラーが出る → まだ未修正 → 本ガイドの回避策を継続

## よくある質問

**Q: 自分の設定が間違っているのでは？**
A: いいえ。これはAnthropic側のインフラの問題です。ユーザー側の設定では根本解決できません。

**Q: allowAllBrowserActions を設定しても直らないのですが？**
A: この設定は操作承認ダイアログの制御用で、ドメインブロックとは別レイヤーです。現時点では効果がありません。

**Q: いつ直りますか？**
A: AnthropicがP1（最優先）で修正中です。具体的な日程は公表されていませんが、v1.0.68で一部緩和されており、次期バージョンでの完全修正が期待されています。

**Q: Claude Desktopチャットでは問題なく動くのはなぜ？**
A: Claude Desktopチャットは「承認済みサイト」リストを正しく参照します。Claude Code（bridge経由）ではこのリストが無視されるバグがあるため、同じ拡張機能でも動作が異なります。
